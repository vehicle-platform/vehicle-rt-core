# CubeMX project image: rt-core, NUCLEO-H743ZI2

**UNVERIFIED ON HARDWARE. The boards are not yet on the desk.** Nothing in this folder has been run on a target. It compiles (Debug, `arm-none-eabi-gcc`), nothing more.

Generated by STM32CubeMX 6.18.0 with STM32Cube FW package FW_H7 V1.13.0. Target: STM32H743ZIT6 (Cortex-M7) on the NUCLEO-H743ZI2.

This project is the pin-plan image from `vehicle-defs/docs/h743-pin-plan.md` (D-118, roadmap T6). It is **not wired to the platform yet**: the `features/`, `services/` and `hal/` layers of this repo do not call into it, and the root CMake build does not include it. Wiring the generated init code behind the `hal/` layer is T13.

Rules:

- The generated code is edited only inside `USER CODE BEGIN` / `USER CODE END` blocks (see `CLAUDE.md`). Everything else is overwritten on regeneration.
- Change the configuration in `rt-core.ioc` (CubeMX), then regenerate. Do not hand-edit generated files.
- This is red-zone, invariant-8 code (clock, reset, MPU, linker script): run `safety-reviewer` after any change.

## Regenerate

1. Install STM32CubeMX 6.18.0 and the STM32Cube FW_H7 V1.13.0 package.
2. Open `cubemx/rt-core.ioc` in CubeMX and press *Generate Code* (toolchain CMake, library files copied only as needed).
3. Or headless, from a script file `gen.txt` (the first line is required):

```
popupwrapper set
config load <repo>/cubemx/rt-core.ioc
project name rt-core
project path <output dir>
project toolchain CMake
project generate
exit
```

Run it with `STM32CubeMX -q gen.txt`. Build with `cmake --preset Debug && cmake --build --preset Debug` inside the generated `rt-core/` folder.

Loading the `.ioc` logs CubeMX messages that cannot be removed: one `Pin<N> (VP_RIF_VS_RIF1) cannot be retrieved for this MCU` and a series of `IP (DMA) : Parameter (...) has Id (...) currently not set`. CubeMX prints them when it reloads a file it saved itself; the DMA configuration is read correctly and appears in the generated code.

## Clock tree (provisional, set 2026-11-27, optimise later)

| Item | Setting |
|---|---|
| HSE | 8 MHz, **bypass** mode (MCO from the on-board ST-LINK) |
| Power | LDO supply, voltage scale VOS1 (400 MHz; VOS0 / 480 MHz not used) |
| PLL1 | M = 4, N = 400, P = 2, Q = 10, R = 2: VCO 800 MHz |
| SYSCLK / CPU (D1CPRE /1) | 400 MHz |
| AXI / AHB (HPRE /2) | 200 MHz |
| APB1, APB2, APB3, APB4 (each /2) | 100 MHz |
| Flash latency | 2 wait states (`FLASH_LATENCY_2`, as CubeMX computes for VOS1 / 200 MHz AXI) |
| FDCAN kernel clock | PLL1Q = 80 MHz (500 kbit/s divides exactly, e.g. prescaler 8 x 20 time quanta) |
| SDMMC1 kernel clock | PLL1Q = 80 MHz |
| ADC kernel clock | PLL2P = 100 MHz (PLL2: M = 4, N = 100, P = 2) |

The FDCAN bit timing, SDMMC divider and every other peripheral parameter are at the CubeMX defaults. DMA stream and request allocation (ADC1, ADC3, TIM3_CH1 on DMA1 streams 0 to 2) is a proposal; the plan says to verify it in CubeMX. The CubeMX board support package (BSP COMMON) is removed from the project because it reserves USART3, which the plan uses for the ST-LINK virtual COM port.

## Open

- FDCAN nominal/data bit timing (500 kbit/s) is not configured yet.
- SDMMC clock divider, ADC sampling times, TIM3/TIM4 periods, I2C timing, SPI1 parameters, UART baud rates: CubeMX defaults.
- FreeRTOS: one default task, CubeMX defaults; the platform tasks come with T13.
- MPU and the linker script are the CubeMX defaults (red zone: need a `safety-reviewer` pass before they are final).
