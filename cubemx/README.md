# CubeMX project image: rt-core, NUCLEO-H743ZI2

**UNVERIFIED ON HARDWARE. The boards are not yet on the desk.** Nothing in this folder has been run on a target. It compiles (Debug, `arm-none-eabi-gcc`), nothing more.

Generated by STM32CubeMX 6.18.0 with STM32Cube FW package FW_H7 V1.13.0. Target: STM32H743ZIT6 (Cortex-M7) on the NUCLEO-H743ZI2.

This project is the pin-plan image from `vehicle-defs/docs/h743-pin-plan.md` (D-118, roadmap T6). It is **not wired to the platform yet**: the `features/`, `services/` and `hal/` layers of this repo do not call into it, and the root CMake build does not include it. Wiring the generated init code behind the `hal/` layer is T13.

Rules:

- The generated code is edited only inside `USER CODE BEGIN` / `USER CODE END` blocks (see `CLAUDE.md`). Everything else is overwritten on regeneration.
- Change the configuration in `rt-core.ioc` (CubeMX), then regenerate. Do not hand-edit generated files.
- This is red-zone, invariant-8 code (clock, reset, MPU, linker script): run `safety-reviewer` after any change.

## Regenerate

1. Install STM32CubeMX 6.18.0 and the STM32Cube FW_H7 V1.13.0 package.
2. Open `cubemx/rt-core.ioc` in CubeMX and press *Generate Code* (toolchain CMake, library files copied only as needed).
3. Or headless, from a script file `gen.txt` (the first line is required):

```
popupwrapper set
config load <repo>/cubemx/rt-core.ioc
project name rt-core
project path <output dir>
project toolchain CMake
project generate
exit
```

Run it with `STM32CubeMX -q gen.txt`. Build with `cmake --preset Debug && cmake --build --preset Debug` inside the generated `rt-core/` folder.

Loading the `.ioc` logs CubeMX messages that cannot be removed: one `Pin<N> (VP_RIF_VS_RIF1) cannot be retrieved for this MCU` and a series of `IP (DMA) : Parameter (...) has Id (...) currently not set`. CubeMX prints them when it reloads a file it saved itself; the DMA configuration is read correctly and appears in the generated code.

## Files that are not generated (T77)

These survive a CubeMX regeneration (CubeMX rewrites `Src/`, `Inc/`, `cmake/stm32cubemx/` and the `.ld`/`.s`, and only the USER CODE blocks of the files in it are kept). The generated files call into them only from USER CODE blocks, with two exceptions that live outside any block and are explained here:

| File | What |
|---|---|
| `User/boot_checks.h`, `User/boot_checks.c` | Reset-cause capture, the stack-free safe state, the naked fault-handler entry with its `.noinit` fault record, the FDCAN pre-start timing check. |
| `User/sbrk_fail.c` | `_sbrk` that always returns `(void *)-1` with `errno = ENOMEM`. |
| `../tools/check_fault_handlers.py` | `objdump` gate: each fault handler starts with `ldr`, `msr MSP` and has no push or call; CI runs it on the Debug and Release images. |
| `../tools/check_image_heap.py` | `nm` gate: fails if the linked image has `malloc`/`free`/`_sbrk`; run by CI (job `renode-boot`, after the image build, on the Debug and Release images, with a malloc canary) and by the CMake target `check_image_heap`. |

Outside USER CODE (the two exceptions):

1. **`cubemx/CMakeLists.txt`** (generated once, "user is free to modify" in its header, so a regeneration does not rewrite it). It adds `User/*.c` and the include paths `User`, `../src` (the pure headers `hal/can_timing.h`, `hal/reset_cause.h`, shared with the host tests) and `../external/vehicle-defs/gen/c/rt_core` (`VEHICLE_CL250_BITRATE`, `PLATFORM_BITRATE`), and **removes the generated `Src/sysmem.c` from the target** (`list(FILTER ... "Src/sysmem\\.c$")`, `CMakeLists.txt:44`). `sysmem.c` is a working newlib `_sbrk` with no USER CODE block, so it cannot be edited in place; the generated `cmake/stm32cubemx/CMakeLists.txt` still lists it (and will after a regeneration), so the removal has to happen in the top-level file. The file stays on disk, unused.
2. **Naked fault handlers.** The four fault handlers are defined by CubeMX in `Src/stm32h7xx_it.c`. Their body is replaced inside the existing USER CODE blocks (`BOOT_FAULT_ENTRY()`), and the `naked` attribute is added as a prototype in the `PFP` USER CODE block (`Src/stm32h7xx_it.c:49-55`); the generated definition picks it up, so nothing outside a block is edited. A `static inline` `always_inline` function is not enough here: the compiler still emits the handler's prologue (a push) before the inlined body at `-O0`, and a push onto an exhausted stack is what must be avoided. A naked handler has no prologue (the handlers themselves do not push; only the function they branch to, after MSP is reset). The asm is a MISRA deviation (DEV-005, `misra/README.md`); CI now also runs the MISRA addon over `cubemx/User`.

## Clock tree (provisional, set 2026-11-27, optimise later)

| Item | Setting |
|---|---|
| HSE | 8 MHz, **bypass** mode (MCO from the on-board ST-LINK) |
| Power | LDO supply, voltage scale VOS1 (400 MHz; VOS0 / 480 MHz not used) |
| PLL1 | M = 4, N = 400, P = 2, Q = 10, R = 2: VCO 800 MHz |
| SYSCLK / CPU (D1CPRE /1) | 400 MHz |
| AXI / AHB (HPRE /2) | 200 MHz |
| APB1, APB2, APB3, APB4 (each /2) | 100 MHz |
| Flash latency | 2 wait states (`FLASH_LATENCY_2`, as CubeMX computes for VOS1 / 200 MHz AXI) |
| FDCAN kernel clock | PLL1Q = 80 MHz (500 kbit/s divides exactly, e.g. prescaler 8 x 20 time quanta) |
| SDMMC1 kernel clock | PLL1Q = 80 MHz |
| ADC kernel clock | PLL2P = 100 MHz (PLL2: M = 4, N = 100, P = 2) |

DMA stream and request allocation (ADC1, ADC3, TIM3_CH1 on DMA1 streams 0 to 2) is a proposal; the plan says to verify it in CubeMX. The CubeMX board support package (BSP COMMON) is removed from the project because it reserves USART3, which the plan uses for the ST-LINK virtual COM port.

## Peripheral settings (T6b, set 2026-11-27, PROVISIONAL under D-134 item 3)

Fixed design choices, to be revisited with measurements on the bench.

| Item | Setting |
|---|---|
| FDCAN1 / FDCAN2 nominal timing | 80 MHz kernel clock, prescaler 10, seg1 13, seg2 2, SJW 2: 16 tq per bit, 500 kbit/s, sample point 14/16 = 87.5 % (CiA 301). Classic CAN, no BRS (`Src/main.c:465-473`, `:518-526`). `FDCAN_CalculateBaudRateNominal=500000` in the `.ioc`. The data-phase fields stay at the CubeMX defaults (unused). |
| FDCAN1 (vehicle bus) mode | `FDCAN_MODE_BUS_MONITORING` (`Src/main.c:468`): never drives the bus, not even the ACK (invariants 1 and D-037). Switching it to normal mode is a T13/T26 step, taken only after a listen-only capture shows 0 error frames. |
| FDCAN2 (platform bus) mode | `FDCAN_MODE_NORMAL` (`Src/main.c:521`). |
| FDCAN message RAM (2560 words, shared) | FDCAN1 at word offset 0: 28 standard filters (28 words) + RX FIFO0 64 x 8-byte elements (4 words each, 256 words) = 284 words, 0 to 283. FDCAN2 at offset 1280 (half of the RAM): 28 filters + RX FIFO0 32 elements (128 words) + TX FIFO 16 elements (64 words) = 220 words, 1280 to 1499. The areas are disjoint with room to grow (`Src/main.c:480-491`, `:533-544`). Both have `ExtFiltersNbr = 0`; the CL250 vehicle bus uses 29-bit IDs, so T13 adds extended filter elements to the FDCAN1 area (and recomputes the word map). |
| IWDG1 | LSI 32 kHz nominal, prescaler /16 (2 kHz tick), reload 1000: 1000 x 16 / 32000 Hz = **0.500 s**, no window (`Src/main.c:620-622`). The LSI spread (about +-30 %) makes the real timeout roughly 0.35 to 0.7 s. Started in `MX_IWDG1_Init`; refreshed provisionally in the default FreeRTOS task loop (`Src/main.c:1025`, every 100 ms). The heartbeat/watchdog module owns the refresh in T13. |
| HSE clock security (CSS) | `HAL_RCC_EnableCSS()` (`Src/main.c:289`). The NMI handler calls `HAL_RCC_NMI_IRQHandler()` (`Src/stm32h7xx_it.c:82`, USER CODE), which clears the flag and calls `HAL_RCC_CSSCallback` -> `Error_Handler` (`Src/main.c:1004`). |
| `Error_Handler` | Disables IRQs, drives PD11/PD3/PD4 (SPI1 chip selects) high through GPIOD BSRR (GPIOD clock forced on), then a system reset request through `SCB->AIRCR`: the stack-free `boot_safe_state()` (`User/boot_checks.h:31`, `static inline` `always_inline`), called from `Error_Handler` (`Src/main.c:1086-1095`). No spin. After the reset the pins are in analog mode until `MX_GPIO_Init` (the BSRR write before it only preloads ODR), so the CS lines need external pull-ups (hardware item, add to `h743-pin-plan.md`), and both CAN transceivers need a TXD pull-up. |
| FreeRTOS | Default task statically allocated (`Src/freertos.c`, `defaultTaskBuffer` / `defaultTaskControlBlock`). `configCHECK_FOR_STACK_OVERFLOW 2` (`Inc/FreeRTOSConfig.h:79`) with `vApplicationStackOverflowHook` -> `Error_Handler` (`Src/freertos.c:59-66`). **Dynamic allocation stays on**, see the open list. |
| SDMMC1 | `MX_SDMMC1_SD_Init` is generated but not called from `main` ("do not generate function call" in the `.ioc` function list), so a missing card cannot stop the boot. `ClockDiv = 2`: card clock = 80 MHz / (2 x 2) = **20 MHz** (<= 25 MHz default speed) (`Src/main.c:654`). Card init moves to a task in T13; a failure there is non-fatal. |
| SPI1 | Prescaler /32 from the 80 MHz kernel clock = **2.5 Mbit/s** (<= 5 MHz device limit, `Src/main.c:688`; /16 would sit exactly on the limit). |
| ADC1, ADC3 | Sampling time 64.5 cycles (`ADC_SAMPLETIME_64CYCLES_5`, `Src/main.c:372`, `:436`). Revisit with the real source impedance. |

`src/hal/can_timing.h` (pure C, header-only `static inline`, no MISRA deviation, host-tested in `tests/host/test_can_timing.c`) checks the timing arithmetic: `can_timing_ok(kernel_hz, prescaler, seg1, seg2, sjw, VEHICLE_CL250_BITRATE)` is true only when every value is inside its FDCAN NBTP range (prescaler 1-512, seg1 1-256, seg2 1-128, 1 <= SJW <= seg2), the rate is exact and the sample point lies in 75 to 90 %. This image is not wired to `src/` yet: **T13 calls `can_timing_ok` before `HAL_FDCAN_Start`** for both controllers.

## Open

- TIM3/TIM4 periods, I2C timing, UART baud rates: CubeMX defaults.
- FreeRTOS: one default task; the platform tasks come with T13.
- MPU and the linker script are the CubeMX defaults (red zone: need a `safety-reviewer` pass before they are final).
- FreeRTOS still uses `heap_4.c` with dynamic allocation enabled (`Inc/FreeRTOSConfig.h:63` `configSUPPORT_DYNAMIC_ALLOCATION 1`, `:72` `configTOTAL_HEAP_SIZE` 15360), so `pvPortMalloc`/`vPortFree` are linked: the residual of the T77 `nm` gate (`tools/check_image_heap.py` reports them as a note; `--forbid-freertos-heap` turns it into a failure once T13 drops `heap_4.c`). The newlib heap is gone from the image: the generated `Src/sysmem.c` is replaced by `User/sbrk_fail.c` (see "Files that are not generated") and the gate fails on any `malloc`, `free` or `_sbrk` symbol. CubeMX does not offer a static-only setting with the CMSIS_V2 interface (its `MEMORY_ALLOCATION` parameter offers only "Dynamic / Static"; a value written into the `.ioc` is ignored). `cmsis_os2.c` itself handles `configSUPPORT_DYNAMIC_ALLOCATION 0` (it checks the macro); what blocks it in this image is the generated `heap_4.c` (`#error` without dynamic allocation) and the generated CMake that always compiles it. Dropping `heap_4.c` from the build and setting the macro to 0 is a T13 step (with `configUSE_MALLOC_FAILED_HOOK 1` -> `Error_Handler` until then).
- Reset cause is captured (`User/boot_checks.c:42`) but not reported: defs has no reset-cause signal or DID (`vehicle-defs/gen` grep, 2026-11-28). Defs follow-up: add one, then the platform UDS server / telemetry can send `boot_reset_cause()` and `boot_fault_kind()`.
- Boot counter: a clock-tree reset loop (a missing HSE resets about every 100 ms, `HSE_STARTUP_TIMEOUT`) is still silent and only visible in `boot_reset_cause()`. A boot counter in the `.noinit` area (reset by a power-on reset) that stops the loop or reports it is open (T13).
- `HAL_RCCEx_GetPeriphCLKFreq` computes the FDCAN kernel clock from `HSE_VALUE` (8 MHz, a compile-time constant), not from a measurement, so the boot-time kernel-clock check cannot catch a wrong HSE crystal; only the CSS and a bench measurement can (T26).
- The FDCAN2 check uses the platform-bus constant `PLATFORM_BITRATE` (vehicle-defs v0.34.0, from `dbc/platform.dbc` `Baudrate`; D-009: both buses 500 kbit/s).
- Residual lockup window before `MX_IWDG1_Init`: a lockup (a fault inside a fault handler) before IWDG1 starts is not reset by anything in software mode. The option byte `IWDG1_SW = 0` (hardware watchdog, started at reset) would close it; it changes the flash option bytes and needs the user's decision. Not done.
- FDCAN pre-start check: `boot_fdcan_start()` exists (`User/boot_checks.c:95`) and its call is in `Src/main.c:166-179` under `RTCORE_BOOT_START_FDCAN`, which no build sets: the image does not start FDCAN (T13), and Renode's M_CAN model does not store NBTP, so the check would fail there. T13 removes the `#if` when it adds the port. FDCAN2 is checked against its own generated constant `PLATFORM_BITRATE` (`BOOT_FDCAN2_EXPECTED_BPS`, `User/boot_checks.h`), FDCAN1 against `VEHICLE_CL250_BITRATE`; both are 500 kbit/s (D-009, `src/hal/README.md`).
- `Error_Handler` now resets the MCU (see the settings table). `SPI1` chip selects PD11 `CS_EGT`, PD3 `CS_ADXL_ARM`, PD4 `CS_ADXL_ENG` start high (`Src/main.c`, `MX_GPIO_Init`, before the pins become outputs); they were low at boot in the first image.
