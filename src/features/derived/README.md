# features/derived

Derived signals of D-070 (catalog section 5), computed on rt-core. **Part 1 and D-103: class A signals whose inputs are DIDs or other computed derived signals (49), plus `data_quality_mask` (D-104), the one exception, fed by the tester's quality record. Part 2a: the class-B ride summaries that are scalars over DIDs and computed signals (section "Rides"), and the 17 D-079 health-window summaries (section "Health windows").** Everything else (signals with sensor/IMU/GPS inputs, binned, per-gear and the 12 window signals the reference does not compute) is reported NOT_COMPUTED with a reason. No bus output and no VSS; the only UDS output is the ride-summary records 0xFD40-0xFD4E of the last closed ride (part 2b, D-098, section "Ride-summary DIDs"). Class-A outputs sit in a static table read by `derived_get()`, ride summaries are read by `derived_ride_get()`; the future logger reads them.

**QM information (D-070 item 5).** It never feeds 0x020, safety-node, the heartbeat or the anomaly safety net. CI greps that `features/cornering`, `features/heartbeat`, `features/uds`, `features/vehicle_republish`, `services/` and `app/comms` never include `features/derived/` (the comms task only calls `services/derived_inputs`).

## data_quality_mask (D-104) — the one computed signal with sensor inputs

`data_quality_mask` (class A, 110 ms) reports the tester's own data quality, so it breaks two derived rules on purpose, and only for this one signal (`classify()` names it):

- **Computed-set exception.** Its `sensor.can_bus_off_count` / `sensor.tester_step_gap_max` inputs are not a sensor source. They come from `services/tester_quality`, ride in the SAME `derived_inputs` record as the DIDs (`quality_valid`, `did_quality[]`, `bus_off_count`, `step_gap_window_ms`, all stamped with `published_ms`) and reach the core through `derived_core_set_quality()` (the glue calls it before every step). Every other signal with a sensor input stays NOT_COMPUTED.
- **A stale DID does not invalidate it.** A stale, never-received or NRC DID is what it reports, so it never uses the DID freshness path: it reads the record's own entry per DID (`present`, stamp, kept apart from the ride-local table) against the DID's `stale_after_ms` from `vehicle_cl250_dids[]`. The output is always a number on its grid (VALID, `flag NONE`).

Rule (the defs description, mirrored by the vehicle-server reference `derived/d104_quality.py`): poll bit `poll_<N>ms` is set when any DID with `poll_period_ms == N` is never received (no sample in this ride), older than its `stale_after_ms`, or its last read got a negative response (NRC other than 0x78, cleared by a positive answer; `uds_client_core_did_last_nrc()`). A DID the tester stopped (D-068) or skipped never counts; rt-core knows its own stop state, so there is no NRC-0x31 heuristic. `bus_off` = the vehicle port's bus-off count is greater than at the previous sample (0 before the first; the remembered count is kept across a ride change and an unknown sample). `tester_stall` = the step-gap window is greater than `VEHICLE_CL250_DATA_QUALITY_TESTER_STALL_GAP_MS`. If the tester quality is unknown (never set, a re-opened client, or the record's `published_ms` older than the signal's `stale_after_ms`), every poll bit, `bus_off` and `tester_stall` are set (unknown counts as bad). The value is the sum of the set bits; bit values, periods, stale limits and the threshold all come from gen/ (`dq_poll_bits[]` pairs the bit macros with gen/ period macros; a DID period without a bit makes the signal NOT_COMPUTED with `DERIVED_NC_GEN`).

- **Not ride-local.** Data quality belongs to the tester, not the ride: the grid starts at the first step after the glue handed quality in (no DID input to wait for) and is NOT restarted by a ride change; the ride-local reset that ignores old-epoch samples does not apply. Each DID is judged by the record's own entry (state NONE = never had a sample since boot, else stamp against `stale_after_ms`), and the remembered bus-off count survives ride changes.
- **Step-gap window.** `uds_client_core_take_step_gap_window_ms()` returns the longest poll gap since its last take; the UDS glue max-merges it into the latched gap of `services/tester_quality`; `derived_inputs_publish()` takes and clears that gap (the reset belongs to the sampler). Because the derived task reads only the newest record and the comms pass publishes far more often, the publish holds the largest taken gap in the record for `DERIVED_INPUTS_GAP_HOLD_MS` (2 x the signal's period) so a 110 ms tick always sees it, then lets it go. A stall longer than the stale limit also reads as unknown quality through the record's stamp.
- **Tests.** `test_derived_quality` (every bit, exclusions, unknown, bus-off against the previous sample, the stall threshold, the sum, arming), `test_derived` (record to core), `test_derived_inputs` (take-and-clear, hold), `test_uds_client_core` / `test_uds_client` (the NRC flag, the window, the glue). No golden vector: the vector selection skips signals with sensor inputs and is unchanged (0 mismatches).

## Rides (class B, part 2a; D-070 parts 2-3, D-087 item 2)

A ride is one D-075 stop epoch of the vehicle tester. `services/tester_epoch` carries `{open, counter}`: the UDS client glue (comms task) sets it after every client step from `uds_client_core_epoch()` (the client core bumps its counter where an epoch opens and clears `open` where the ECU goes absent), and `derived_inputs_publish()` copies the two fields into the SAME snapshot record as the DIDs; the derived task never reads the client and the core never duplicates `ecu_absent_timeout_ms`.

- **Detection.** `derived_core_step_epoch()` closes the open ride when the counter differs (`!=`: any jump size, wrap-safe) or `open` is false, then opens a new one if an epoch is open. Close + reopen in one record (counter + 1, `open` still true), a jump by more than 1, the uint16 wrap and open -> false -> true are unit-tested. The record of the step that closes a ride is never added to it.
- **Fresh state.** A new ride resets the class-A state to ride-local (grids anchored at the ride's first samples, integrals, windows, the altitude reference, the stop event) and ignores the DID samples the core already holds (the old epoch's, equal stamps) until a new sample arrives, like the reference evaluating every ride on its own. Without an epoch (`derived_core_step()`, or `known == false`) there is no ride and class A runs as in part 1.
- **Computed set (42 = 12 + the 13 D-103 summaries + the 17 D-079 window summaries below, from the gen table: class B, `rt_core_ready`, scalar, inputs only DIDs or computed signals, a formula in `derived_ride.c`; the golden vectors have the same 42, plus the 2 unbounded ones below):** `ride_distance`, `ride_time`, `ride_idle_time` (last valid class-A output of the ride), `ride_stop_count` (valid stop events), `ride_fuel_used` (time integral of the fuel rate, a sample held until the next one but never beyond that DID's own `stale_after_ms`, D-087; the segment still open at the close adds nothing, like the reference), `ride_fuel_consumption` (used / distance x 100; no distance is STANDSTILL), `ride_ltft_mean`, `ride_stft_std` (population, Welford), `ride_coolant_rate_max`, `ride_start_coolant_temp`, `ride_end_coolant_temp`, `ride_start_intake_temp` (first / last DID sample of the ride). The accumulators of the integral and the means are `double` (small increments over a long ride), results float32 through the gen range check (outside it: OUT_OF_RANGE, never clamped).
- **The 13 D-103 summaries (LR21b), rules of `vehicle-server` `derived/d103_summaries.py`:** max of the valid rows (`ride_heat_soak_max`, `ride_idle_rpm_std`), first valid row (`ride_cranking_dip`, `ride_rest_voltage`), last valid row (`ride_idle_rpm_drift`), counts of valid event rows (`ride_shift_count`, `ride_launch_count`: 0 without rows, never INVALID_INPUT), flag seconds (`ride_cold_abuse_time`, `ride_over_rev_time`, `ride_lugging_time`: every row of the class-A flag counts, a valid row with value 1 adds the time to the next row capped at the flag's own `stale_after_ms`, the last row adds nothing, no valid row is INVALID_INPUT, `double` seconds), `ride_warmup_time` (first ENGINE_SPEED > 0 to the first COOLANT >= operating; flags STARTS_WARM, NEVER_WARM), `ride_thermal_cycle_count` (cold below `derived_cold_coolant_degc`, then >= operating: +1; always a value), `ride_fan_on_temperature` (first battery drop >= the step between consecutive battery samples no further apart than the battery's `stale_after_ms`, at rest in the idle band with the coolant above the minimum at BOTH samples, speed / rpm / coolant each fresh within its own DID limit; the value is the coolant at the second sample; else NO_FAN_STEP). Thresholds are the gen/ `VEHICLE_CL250_DERIVED_*` / `VEHICLE_CL250_RIDE_FAN_ON_*` macros. The fan step settles at the end of each ingest (`derived_ride_settle`) so the DIDs of the same step are all in.
- **The grid end of the reference.** `engine.py` evaluates a grid signal only up to the last time every input has a sample (`end = min` of the inputs' last times; a derived input contributes its last grid tick). The summaries over the grid signals (heat soak, cold abuse, over rev, lugging, idle RPM std / drift) therefore must not see the rows after it. Each such row waits in a bounded ring and is confirmed once every input has a sample at or after its tick (`ride_confirm_rows()` in `derived_core.c`, `derived_ride_advance()`); rows still waiting at the close are dropped. The rings share one pool of 306 rows (`DERIVED_RIDE_TAIL_POOL`; 388 before defs v0.26.0 dropped cold abuse's unused oil-temperature input), each signal with its own cap `DERIVED_RIDE_TAIL_CAP_*` = ceil(max input `stale_after_ms` / period) + 2 (heat soak 139, cold abuse 57, over rev 5, lugging 57, idle RPM std / drift 24 each): a row is valid only while every input is fresh, so when a ring is full the oldest row is past every input's stale limit (an invalid row in the reference too) and is confirmed early, which changes no result. gen/ has period and stale only as table data, so `derived_ride_tail_fits()` checks the caps at init like the `DERIVED_WIN_*_CAP`: a cap that is too small makes the signal NOT_COMPUTED (reason SIZING), never silently truncated. The older part-2a summaries do not wait (their golden values match without it).
- **Left NOT_COMPUTED with `DERIVED_NC_UNBOUNDED`:** `ride_aggressiveness_score` (a p95 over the whole ride) and `throttle_torque_lag` (a median over every throttle step plus a cross-correlation per step) need every sample of the ride, which is not bounded on the MCU.
- **Not computed, with a reason:** binned and per-gear signals (`operating_point_time`, the time-at-temperature histograms, `ride_final_drive_ratio`: reason ELEMENTS), signals with sensor inputs or inputs that are not computed (GPS, bus health, tester health, ...: NO_FORMULA / NOT_READY), the 12 window signals the reference does not compute (not `rt_core_ready`: pump current, crank voltage/current/resistance/duration, vibration, final-drive and VE residuals; NOT_READY) and the rest of class B.
- **Output.** `derived_ride_get(CURRENT | PREVIOUS, sig, &out)` (derived task only): CURRENT is the open ride as it would close now, PREVIOUS the last closed ride (one record, replaced at the next close); NO_DATA while there is none. The last closed ride also goes out as the UDS records 0xFD40-0xFD4E (part 2b, below); no CAN, no persistence: **a power-down close is out of 2a** (D-045 logging comes later), so a ride that ends with the power loses its summary; the epoch flag and counter are the only ride signal.
- **Memory.** Running state plus the closed record only for the computed signals: `derived_ride_t` is in `derived_core_t` (see Memory).

## Health windows (D-079, E-30 (11) part 2)

`derived_windows` is the pure state machine of the five windows of gen/ `vehicle_cl250_window[]` (conditions, stable bands, `opens_on`, min / max duration, record DID; nothing hand-written but the summary arithmetic), a port of vehicle-server `derived/health_windows.py` and `health_window_summaries.py`. The derived core pushes each new DID sample and each `gear_estimate` row of the open ride (valid or not); `derived_windows_run()` sorts the step's events by time (window inputs before statistics samples of the same time) and feeds them; `derived_windows_end()` runs at the ride close.

- **Timeline.** Per window the points are the sample times of its condition, stable and trigger inputs plus each input's stale instant (`sample + stale_after_ms + 1`) when no newer sample arrived by then. An expiry is a point only if some window sample exists at or after it, so it is processed when the next window sample arrives and never at the ride end (a ride that ends with the ECU absent closes its instance at the last sample, not at the stale instant). A lost input closes the instance at its stale instant.
- **Rules.** `condition` windows re-arm only after the conditions were not met once; `key_on` opens at the first point only; `engine_start` / `engine_stop` open on the next ENGINE_SPEED transition (consecutive samples within that DID's `stale_after_ms`) when the conditions hold. Close reasons: max duration (clamped to open + max, qualifies), conditions, stable band exceeded, engine zero / unknown (`engine_start`), ride end at the last point. An instance qualifies by max duration or after `min_duration_ms`. Counts are always a value (0 without a window); every other summary is invalid with `DERIVED_FLAG_NO_WINDOW` (20) without a qualifying instance, NO_DATA (14) / INSUFFICIENT_SAMPLES without samples.
- **Statistics of the first qualifying instance** (means in `double`, as the reference): W1 battery / coolant / intake / ambient / MAP / baro means (rest voltage, sensor spread, MAP-baro delta, warm restart against `window_cold_soak_max_delta_degc`); W3 engine-speed spread and drift (second half minus first half, middle = open + duration / 2, from the core's ENGINE_SPEED history ring when the instance closes), MAP spread, STFT mean and sample std (n - 1); W5 first / last coolant and the Newton-cooling tau (least squares of ln(T - mean ambient) over the elapsed seconds, tau = -1 / slope; fewer than 3 positive differences or zero variance INSUFFICIENT_SAMPLES, slope >= 0 NO_DATA) from a buffer of `DERIVED_WIN_POST_STOP_COOLANT_CAP` = 1 800 000 / 800 + 2 = 2252 coolant samples, 4 B each (uint16 time since the previous stored sample + the DID's raw integer, rebuilt with the gen/ factor and offset exactly like `vehicle_cl250_decode()`; checked against gen/ at init: SIZING, also when the coolant `stale_after_ms` exceeds 65535 or a raw does not round-trip). A value that is not an exact raw or a gap above 65 s between stored coolant samples is `broken` (MATH_ERROR). A statistics sample waits in a pending list (`DERIVED_WINDOWS_PEND_CAP`, sized from gen/) until the window point at or after it is evaluated, because that point may close the instance (the sample at a condition close is outside) and a sample after the last window sample is only inside once a later window sample proves the expiry real. A bound exceeded at run time (pending list, event queue, coolant buffer) makes the window's summaries MATH_ERROR, never a wrong value.
- **Not matched exactly.** `gear_estimate` rows (W4's only derived input) enter the cruise window as the core evaluates them. The reference lets a grid signal stop at the last time every input has a sample, so rows after that time do not exist there; the golden vectors never hit the difference, but a ride that ends while the gear grid still ticks could close its cruise instance on a later invalid row instead of at the last speed sample. Only `window_cruise_count` depends on it.
- **CURRENT** counts and values include the open instance as if the ride ended at the last evaluated point.

## Ride-summary DIDs (part 2b, D-098)

- **Closed counter.** `derived_ride_close()` keeps the closed ride's epoch counter (`prev_counter`), the D-098 header counter, not the counter of a ride opened in the same record; `derived_core_ride_closed(core, &counter)` is false until the first close. Unit-tested: close + reopen in one record, the 65535 -> 0 wrap, and the restart when the tester re-opens (`{closed, 0}`, then counter 1 again).
- **Encode in the derived task.** After each step `derived_step()` compares the ride's `closed_count` with the last one it published; on a change it calls `ride_records_publish(closed_ride_value, closed, counter)` (the one producer call site, CI), which runs the pure generic writer `services/ride_records_core` over `platform_uds_ride_fields[]` straight into the snapshot's write slot. `closed_ride_value()` is `derived_ride_get(PREVIOUS, signal)`: VALID gives the value, NOT_COMPUTED / NO_DATA / INVALID give NOT_AVAILABLE. So the 70 conversions run once per ride close, here, and the comms pass only copies bytes (`ride_records_take()` + the server's read, `services/README.md`). The boot records (no ride) come from `ride_records_init()`.
- **Rounding.** float32 `(v - range_min) / resolution`, then `lrintf` (FE_TONEAREST, round half to even, never `roundf`/`lroundf`), after an `isfinite` check and the bounds -1 < x < raw_max + 1 (keeps `lrintf`'s 32-bit `long` defined on the M7); a rounded raw outside 0..raw_max is NOT_AVAILABLE, never clamped. `-fno-math-errno` as for the core; the file refuses `-ffast-math`.

## Task placement and the cross-task input

`services/vehicle_signals` is single-task (the UDS client writes it in the comms task), so the derived task never reads it. `derived_inputs_publish(now)` runs once per pass in `comms_pass()` as the last call, after `uds_server_step()` (nothing later writes `vehicle_signals`, and no frame work waits for the copy): one bounded pass over the 40 DIDs copies {value, sample stamp, state} into a `services/snapshot` (three static slots, initialised INVALID before either task starts). `derived_step()` is the one consumer call site and copies the whole record out in the same call (snapshot second-reader rule). The record carries a pass counter; `test_derived_inputs_stress` (ASan/UBSan and TSan) shows a record is never torn. Entries keep the sample's own stamp, so a stalled comms task makes every output stale by the signals' own limits.

The derived task runs below the EKF and below the comms task (CLAUDE.md rule 4, D-070 item 5): no blocking, no lock, static memory, every loop bounded by a compile-time size. In the host program it is stepped from the main loop after `comms_pass()`. The H7 task wiring comes with the H7 port. `derived_step()` and `derived_get()` are for the derived task only; a future logger runs in that task or gets its own snapshot of the output table.

## Rules (the reference engine: vehicle-server `derived/engine.py`, `context.py`)

- **Computed set** is decided at init from the gen table (class A, `rt_core_ready`, inputs only DIDs or computed derived signals with a lower index, a formula in the dispatch switch, windows that fit the sample buffers). It is not a hand-written list of 49: `test_derived_core` checks that it equals the set in the golden vectors (49 = 42 point/window/state/integral signals + 7 events; no difference). Evaluation order is the gen index order; a test asserts every derived input comes earlier.
- **Sample-and-hold with age.** A value is usable while `age <= stale_after_ms` (age equal to the limit is fresh, one more is stale, like the reference). The limit is the DID's own `stale_after_ms` from `vehicle_cl250_dids[]` for a DID input (D-070; e.g. 300 ms for the speed even where a signal's own limit is 330) and the producer's `stale_after_ms` for a derived input. The glue passes the sample stamp and the core applies that limit, the same one `vehicle_signals` uses for its STALE. Every DID input is judged this way, the event signal `stop_event` and (later) the class-B summaries included (D-087 item 1); the reference's 3-poll age is gone. A sample counts as lapsed when older than the longest limit and stays unusable until a new sample (a wrapped counter can not revive it).
- **Grid.** Each signal has a `period_ms` grid that starts at the latest first-sample time of its inputs (a derived input: the producer's start). A step evaluates the latest due tick of a signal (no catch-up) and stamps the output with the tick. Called every ms (tests) it is the reference exactly; called every few ms it is up to one step late.
- **Range, never clamped.** A result outside the gen `[min, max]` is invalid with OUT_OF_RANGE (the unranged value is kept for diagnostics). A non-finite input or result is MATH_ERROR (the reference reports a non-finite result as out_of_range; its inputs can not be NaN).
- **Flags** are the reference's, in the reference's input order (STALE, INVALID_INPUT, INSUFFICIENT_SAMPLES, STANDSTILL, NO_CONSUMPTION, NO_POWER, ENGINE_OFF, NOT_MOVING, NO_GEAR, NOT_APPLICABLE). Every input read must be declared in the signal's gen inputs, else MATH_ERROR (fail closed).
- **Windows** (acceleration, jerk, fuel average, coolant and oil rate, plus the D-103 RPM, battery, fuel and acceleration histories): fixed ring buffers per DID or derived producer, sized at compile time. Since defs v0.26.0 the `DERIVED_WIN_*_CAP` (and the W5 post-stop coolant cap) are computed from gen/'s compile-time copies of the table data (`VEHICLE_CL250_POLL_MS_*`, `_PERIOD_MS_*`, `_WINDOW_MS_*`, `_MAX_DURATION_MS_*`) as `window / period + 2`, the maximum over the windows a history serves; nothing is hand-derived (ISSUES E-30 (10)). init still checks them against the runtime tables: a window that does not fit makes its signal NOT_COMPUTED (reason SIZING), never silently truncated, and a test asserts none does.
- **Integrals** (trip distance, trip time, idle time) follow the reference's hold rule: a value is held from a sample until the next sample but never longer than the shortest remaining freshness of its inputs, so a gap adds nothing. The accumulators are `double` (a long ride would lose small increments in float32); the M7 has a double-precision FPU.
- **`stop_event`** is not on a grid: one row per stop at the time the vehicle moves off (value = duration in s, the reference's rule: speed 0 after moving, engine running, a gap longer than the speed DID's own `stale_after_ms` ends it; the engine must have a fresh RPM by that DID's own limit).

## Tests

- `test_derived_core`: golden replay of the five scenarios (46 191 rows, stepped every ms): grid time, valid flag and flag code exact, values within the per-signal tolerance (resolution / 2), equal counts of rows and core evaluations, event rows; zero rows needed the boundary allowance (the rule is documented at the top of the test; the skip list is asserted empty). Plus hand-computed unit tests (torque and power, air density and altitude, fuel formulas, residuals, gearbox ratio and gear, zero-guard flags, window slope and mean, integrals across a gap, the stop event and its gap rule, staleness at the limit and one past, range without clamping, NaN/inf, lapse, late steps, coarse stepping on the grid, not-computed reasons, dependency order, computed set = golden set) and the pinned-gen check below.
- **Vectors vs the pinned gen table.** The expected outputs depend on the gen table the vectors were generated from. `test_vectors_match_the_pinned_gen_table` hashes (FNV-1a) everything of gen/ they depend on (period, stale limit, window, range, resolution and inputs of every vector signal, the poll period of every DID read, and the twelve vehicle constants the generator uses) and compares it with the value recorded in the test; it also checks `abs_tol == resolution / 2` and that inputs follow the poll periods. A defs bump that changes any of them fails this test with "regenerate the vectors", not with unrelated value differences. The vectors' banner names the defs version they were generated from; this test, not that banner, decides whether the pinned table still matches.
- `test_derived_windows`: 30 hand-computed cases of the window machine (W1 close by condition / stale instant / max duration clamp with its boundary sample / ride end, W2 transition, consecutive rule, engine zero, unknown, re-arm, W3 statistics and re-arm after a max close, W4 stable band and unknown gear, W5 statistics and tau with its failure flags, the pending / event / buffer bounds, gen checks).

## Memory (D-070 item 6)

Static RAM with the ride summaries (part 2a) and the D-103 histories (LR21b: with the 13 class-B summaries host `sizeof(derived_core_t)` is 23 952 B and `derived.c` BSS 23 704 B, +3 568 B over 20 136 B, of which the 388-row waiting pool was 3 104 B, 2 448 B with 306 rows since defs v0.26.0; `derived_ride.c` text 1 172 B to 3 184 B, `derived_core.c` 5 780 B to 6 146 B), measured with `arm-none-eabi-size` on the M7 release build: host `sizeof(derived_core_t)` is 20 336 B after D-103 (the D-103 histories add about 7.7 KB); the M7 release object grows from 5 470 B to 10 636 B text (+5 166 B) and `derived.c` from 12 388 B to 20 136 B BSS (+7 748 B). Before D-103 the M7 build was about 13.9 KB (`derived.c` 12 388 B; `derived_inputs.c` 1 493 B; `tester_epoch.c` 4 B; host `sizeof(derived_core_t)` 12 592 B). That is **over D-070's estimate of at most about 10 KB for all signals**, already before D-103 for 28 signals: the 60 s fuel-consumption window keeps 547 speed samples (4.4 KB), the biggest single block, and the per-signal tables over all 141 gen indices take 5.6 KB (host). Recorded here per D-070 item 6; trimming options are a shorter window or a running-sum average, and a table over the computed signals only. When the H7 linker script lands, this block must stay out of the EKF's DTCM.

Part 2b (D-098, measured the same way, D-088): **+837 B static** = `ride_records.c` 833 B (three snapshot slots and the comms copy of the 205 B of records, the snapshot word, init flag, skip counter) + 4 B in `derived.c` (the last published close; `prev_counter` fits in `derived_ride_t`'s padding). Flash: `ride_records_core.c` 644 B, `ride_records.c` 308 B, about 160 B more in the derived glue, core and UDS server. Like the rest of this module it stays out of the EKF's DTCM.

D-079 windows (this change, measured on the M7 release build): `derived.c` BSS 23 704 B to 45 352 B (**+21 648 B**: `derived_windows_t` in the ride accumulator, of which the 2252-sample post-stop coolant buffer is 9 008 B), `derived_windows.c` text 5 371 B, `derived_ride.c` text 3 184 B to 3 284 B, `derived_core.c` text 6 146 B to 6 422 B. This is the largest block of the module after the history rings; the tau buffer is the only reason: it needs every coolant sample of a up-to-30 min post-stop instance because ln(T - ambient) depends on the instance's final mean ambient. Trimming option: a shorter max duration in defs, or a coarser coolant sample store.
